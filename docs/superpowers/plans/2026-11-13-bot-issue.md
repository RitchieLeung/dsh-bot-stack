# 事务管理模块 Implementation Plan（自研 `dsh-plugin-bot-issue`）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 自研一个独立插件 `dsh-plugin-bot-issue`（与知识库 `dsh-plugin-bot-knowledge` 平级），
实现「事务」模块：issue 作为每件事的起点，主 Bot 用工具管理，派工走 dscord 的 `dispatch_work`，
工作者闭环后把结果写回 issue。

**Why not fork dsh-orchestrator:** 已试，host half 与 dsh 0.2.2-rc.1 代码层面不兼容，
装进 profile 后整个 dsh web 起不来。改为自研，沿用 `dsh-plugin-bot-knowledge` 的成熟形态
（Host + Client 两个 half、SQLite、纯 handler、node --test）。

**Tech Stack:** 纯 JS（ESM）、`node:sqlite`、`@deepseek-ai/dsh-tools`（defineTool）、React（面板）、`node --test`。

**Spec:** `docs/superpowers/specs/2026-11-13-bot-issue-design.md`

## Global Constraints

- 与知识库平级：`~/.dsh/bot/workspace/bot-issue/`，plugin row `id: bot-issue`。
- 主 Bot 不写死：读 dscord `state.json` 的 `mainBotIds`（Mac 鲸鱼 / 146 小欣）。
- 派工只复用 `dispatch_work`，不新增 worker 机制。
- 已派工（dispatched）不能重复派工。
- issue 数据存本机 `~/.dsh/bot/issue/issue.sqlite`。
- 闭环者写回：worker `work_report done/failed` → 写回轮询 → issue `in_review`/`failed`。

## Review Focus

- 知识库插件不得被改动（事务是独立模块，不嵌套）。
- 派工失败（无 origin / 主 Bot 忙）时 issue 保持原状态并可重试，不能卡死。
- 写回时 issue 已被人为 cancelled → 不覆盖。
- 同一 issue 重复启动 → 不重复派工（WIP 期间禁用）。
- 主 Bot 自己创建的 issue 自动进入 open，不经人工确认。
