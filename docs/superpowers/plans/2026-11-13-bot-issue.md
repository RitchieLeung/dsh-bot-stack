# 事务管理模块 Implementation Plan（fork dsh-orchestrator）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `dsh-orchestrator`（Apache-2.0）基础上改造成 dscord 的「事务」模块：issue 作为每件事的起点，主 bot 用工具管理，派工走 dscord 的 `dispatch_work`，结果闭环回写。

**Architecture:** fork `dsh-orchestrator`，保留 domain/service/rpc/tools/client（约 4000 行），重写 `session-link.ts`（约 960 行）把「workspace 分 board + `ctx.agents` 开 session」换成「主 bot 单 board + dscord `dispatch_work`」，裁掉 `plan-loop.ts`，轻改 command/skill。

**Tech Stack:** TypeScript、Cordis、Zod、Schemastery、React、esbuild、`node --test`。

**Spec:** `docs/superpowers/specs/2026-11-13-bot-issue-design.md`

## Global Constraints

- 基线：`~/.dsh/bot/workspace/dsh-orchestrator` 已 clone，`npm install --ignore-scripts` 后 build 通过、100 测试全过。
- 主 bot 不写死：取 dscord 主 bot 标记（Mac 鲸鱼 / 146 小欣）。
- 派工只复用 `dispatch_work`，不新增 worker 机制。
- 保留原测试；改动模块必须补/改对应测试。
- 安装走工作区目录，不手写 profile。

## Review Focus

- board 只应有一块（主 bot 的），不能再按 repo 分身。
- 派工失败（无 origin/主 bot 忙）时 issue 保持 `todo` 并可重试，不能卡死。
- worker 结果写回时 issue 已被人为 cancelled → 不覆盖。
- 同一 issue 重复启动 → 不重复派工（WIP 期间禁用）。
- 主 bot 创建的 issue 自动启动，不经人工确认。
