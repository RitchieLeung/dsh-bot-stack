# 事务管理模块（issue）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 dsh 增加一个「事务」插件：issue 作为每件事的起点，主 bot 用工具创建/更新/派工/评论，面板展示列表与详情，worker 结果闭环回写 issue。

**Architecture:** 新插件 `dsh-plugin-issue`（Host + Client 两个 half，形态照抄 `dsh-plugin-bot-knowledge`）。Host 持有 SQLite（issues/comments/dispatches）、HTTP 路由、主 bot 的 5+1 个 dsh 工具；Client 注册侧边栏「事务」+ 主面板。派工复用 dscord 的 `dispatch_work`，需要两处 fork 改动：前台工具白名单可配置、允许 issue 作为 origin 无消息派工。写回由插件的 writeback 模块盯 dscord 的任务台账（`native-bridge.json`）完成。

**Tech Stack:** Node ESM、`node:sqlite`（DatabaseSync，readOnly + 写库）、Cordis 插件（ctx.effect / ctx.connection.fetch.register / ctx.slots.register）、React（client half 用 `h` 而非 JSX）、node:test。

**Spec:** `docs/superpowers/specs/2026-11-13-bot-issue-design.md`

## Global Constraints

- 主 bot 不写死：取 dscord 的 `mainBotIds` / 主 bot 标记，Mac 上是鲸鱼、146 上是小欣。
- 派工只复用 `dispatch_work`，不新增 worker/任务机制。
- 面板是独立插件，Host/Client 分离，沿用 bot-knowledge 的形态与视觉语言。
- 插件安装走 `plugin_manager install_bundle`（工作区目录为 target），不手写 profile。
- 所有 SQLite 写操作用 `PRAGMA journal_mode=WAL` 与 `busy_timeout`，读操作可选 readOnly。
- 状态机：`open → discussing → dispatched → in_progress → done | failed | cancelled`。
- 工具必须在 dscord `FRONT_TOOLS` 中放行，且放行清单必须可配置（extra front tools）。

## Review Focus

- 面板在 issue 不存在/已关闭时打开详情 → 应显示空态而非崩溃。
- 主 bot 的 `issue_update` 传入不存在的 issue id → 返回结构化错误而非抛异常。
- worker 结果写回时 issue 已被人工 cancelled → 不覆盖 cancelled，追加评论说明。
- 多个 worker 同时完成 → writeback 幂等（同一 taskId 只写一次）。
- 派工登记重复（同一 issue 再次启动）→ 旧的 dispatch 记录保留，status 回到 discussing。
